# 个人因子挖掘 SOP（机构级 · 聚宽落地版）

> 设计哲学（来自机构内部实践 + AAAI 2026《Navigating the Alpha Jungle》）：
> - **AI 生成因子只占 20% 工作量，剩下 80% 是规则校验与风控。** 生成是起点，不是终点。
> - 没有规则约束的 AI 因子 = 高级版数据挖掘过拟合。底层环境一塌糊涂，模型再强也落不了地。
> - 目标不是"单次生成神因子"，而是**持续迭代、自我进化的闭环体系**。
> - 聚宽侧可工程化复现论文的"回测多维评分 → 反馈引导生成"核心创新。

---

## 阶段零：基建标准化（先搭地基，再谈 AI）

> 视频第一步：统一口径 → 独立沙箱 → 死权限边界。90% 个人玩家直接跳过这步。

### 0.1 统一因子计算口径（消除幻觉根因）
- 统一字段名、计算口径、时间对齐（对齐到交易日、前复权/真实价模式固定）。
- 同一指标全公司算出来必须是同一个值，否则 AI 生成的字段在数据库里可能根本不存在。
- **聚宽落地**：
  - 数据字典 Bookmark（按需查，不必通读）：`valuation` / `indicator` / `finance`(fundamentals) / 行业概念 `plateData`。
  - 建一个**统一的预处理流水线**函数：`winsorize`（缩尾去极值）、`winsorize_med`（中位数去极值）、`neutralize`（行业/市值/风险中性化）、`standardlize`（Z-Score 标准化）。所有因子必须经过同一管线。

### 0.2 独立沙箱回测环境（测试与生产隔离）
- AI 随便试错，不能污染真实数据。
- **聚宽两个 API 世界必须分清**（新手最大坑）：
  | 环境 | 用途 | 典型 API |
  |---|---|---|
  | 研究环境（Notebook） | 离线因子挖掘、分析（= 论文"生成+评估"循环） | `jqdata` / `jqfactor.calc_factors` / `analyze_factor` / `finance.run_query` |
  | 回测环境（策略） | 跑策略、撮合、下单 | `get_price` / `get_fundamentals` / `order` / `jqfactor.Factor` |
- 论文 LLM+MCTS 的"生成→回测评分→改进"循环，在**研究环境**用 `jqfactor` 实现；通过的因子再去**回测环境**落地。

### 0.3 死代码执行权限边界（白名单）
- 提前锁死：哪些字段能碰、哪些算子能用。
- **聚宽落地**：自定义 `jqfactor.Factor` 基类，统一入口 `calc_factors(securities, factors, start_date, end_date)`；算子白名单可借鉴论文 Table 2（Ma/Std/Corr/Rank/Delay/Diff 等约 30 个算子），禁止调用未授权数据源。

## 阶段一：约束内生成（绝不开放式下指令）

> 视频第二步：给 LLM 一套白名单知识库，只在此范围内生成，每条逻辑可溯源。

### 1.1 白名单知识库（机构料库式 AI，非野生 AI）
必须沉淀以下内容，每次生成前注入上下文：
- 历史有效因子库（聚宽因子库 / Alpha191 / Alpha101 可作种子）
- 内部研报库、学术论文库（含《Navigating the Alpha Jungle》等）
- 标准字段词典（数据字典提炼）
- **过去所有失败实验的复盘日志**（最关键：让 AI 避免重复踩坑）

### 1.2 生成策略（论文工程化思路）
- **LLM + MCTS 协同**：LLM 基于"当前公式 + 可用字段 + 算子库 + 历史高质量因子"提出改进；MCTS 依据回测反馈选分支。
- **多维反馈引导**：候选因子回测后算 5 维分数，反向指导搜索（见阶段二映射）。
- **FSA 频繁子树规避**：从因子库挖掘"频繁闭合根基因"（忽略参数只看结构），指令 LLM 避开，防同质化——本质是自动化的"失败模式复盘"。
- 动态预算：出现新纪录则搜索预算 +1。

## 阶段二：三层阶梯质控（能闯全关的因子寥寥无几）

> 视频第三步：基础量化初筛 → 人工逻辑校验 → 多场景压力测试。100 个候选常只剩 1–2 个。

| 层级 | 目的 | 聚宽落地 | 淘汰比例 |
|---|---|---|---|
| **第一层 量化初筛** | 机器批量跑指标，剔除硬伤 | `analyze_factor` 出 IC / RankIC / 换手率 tear sheet；覆盖率、IC 稳定性 | ~70–80% |
| **第二层 人工逻辑校验** | 有无经济逻辑支撑？还是数据巧合拟合？ | 研究员逐条判断，回测再好无逻辑也废 | 严格 |
| **第三层 多场景压测** | 分市值/行业/牛熊 + 真实成本 | 变换 `universe`、行业分类、`set_order_cost` 真实交易成本/冲击成本 | 极端环境 |

### 论文 5 维评估 ↔ 聚宽能力映射
| 论文维度 | 聚宽对应 | 说明 |
|---|---|---|
| Effectiveness 效果 | `far.ic` / `far.ic_monthly`（RankIC，均值>0.03 有效） | 直接支持 |
| Stability 稳定性 | 月度 IC 标准差 / `calc_autocorrelation` | 直接支持 |
| Turnover 换手 | `create_turnover_tear_sheet` | 对应交易成本 |
| Diversity 多样性 | 自建：因子间 `corr` 矩阵（要求<0.8） | 聚宽无现成，需外层补 |
| Overfitting Risk 过拟合 | 自建：样本内外 IC 衰减 / LLM 语义评估 | 聚宽无现成，需外层补 |

## 阶段三：因子生命周期管理（闭环，不是终点）

> 视频第四步：入库不是万事大吉，要持续监控 + 写回知识库。

- **持续监控**：每个因子的 IC 衰减、相关性变化、风格暴露。失效 / 拥挤 / 逻辑破坏 → 立即退役。
- **知识库回流**：成功因子 + 失败案例重新写回白名单知识库喂给 LLM，下次自动避坑、复用有效逻辑，越挖越准。
- **聚宽落地**：定期批量重跑 `analyze_factor` 监控；维护因子库快照与版本（JSON/CSV 记录每版因子公式、参数、评分、退役原因）。
